
Відповіді на контрольні питання (Лабораторна робота №15)

1. Які переваги дає використання інтерфейсу FormData для збору даних форми порівняно з ручним зчитуванням властивостей value для кожного інпуту окремо?
• Відповідь: FormData автоматично збирає дані з усіх полів форми, які мають атрибут name, в один об'єкт. Це позбавляє необхідності вручну писати велику кількість повторюваного коду типу document.getElementById(...).value. Такий підхід значно скорочує обсяг коду, робить його гнучким до додавання нових полів у HTML та спрощує подальше структурування даних або їх відправку на сервер.
2. Чому перед проведенням валідації текстових полів важливо застосовувати метод .trim()? Яку проблему користувацького введення це вирішує?
• Відповідь: Метод .trim() видаляє випадкові або навмисні пробіли з початку та кінця текстового рядка. Це вирішує поширену проблему, коли користувач під час введення імені чи пошти випадково ставить пробіл (наприклад, при копіюванні або через роботу автозаповнення на мобільному телефоні). Без застосування .trim() строга валідація регулярними виразами видасть помилку, хоча фактично дані введено правильно.
3. Опишіть логіку роботи регулярного виразу /^\+?380\d{9}$/ для перевірки українського номера телефону. За що відповідає кожен символ у цьому виразі?
• Відповідь:
	• ^ — позначає початок рядка (щоб перед номером не було зайвих символів).
	• \+? — екранований знак плюс, який завдяки символу ? є опціональним (може зустрічатися 0 або 1 раз).
	• 380 — обов'язковий міжнародний телефонний код України.
	• \d{9} — рівно 9 цифрових знаків після коду (код оператора та сам номер).
	• $ — позначає кінець рядка (щоб після 9 цифр користувач не міг додати нічого зайвого).
4. У чому полягає різниця між методами рядків .replace() та .replaceAll()? В якому випадку при очищенні номера телефону доцільно обрати саме .replaceAll()?
• Відповідь: Метод .replace() замінює лише перший знайдений збіг у рядку, тоді як .replaceAll() замінює абсолютно всі знайдені збіги по всьому рядку. При очищенні телефону доцільно використовувати саме .replaceAll(), оскільки нам потрібно повністю видалити всі наявні пробіли, дефіси та дужки, а не лише першу дужку чи перший дефіс.
5. Які переваги декларативного підходу (використання методів filter(), map(), reduce()) порівняно з традиційними імперативними циклами for чи forEach при обробці масивів даних на клієнті?
• Відповідь: Декларативний підхід фокусується на результаті («що зробити»), а не на покроковому процесі («як зробити»).
	• Код стає набагато коротшим, чистішим і легшим для читання.
	• Не потрібно створювати додаткові порожні тимчасові масиви чи змінні-лічильники вручну.
	• Кожен метод має чітку логіку: filter() — відбирає збіги за умовою, map() — трансформує структуру об'єктів у масиві, reduce() — згортає масив у одне підсумкове число (наприклад, суму). Це мінімізує появу випадкових помилок розробника.
